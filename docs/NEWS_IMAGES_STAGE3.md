# Этап 3: главная фотография к каждой новости

## Функциональность

- В уже загруженном HTML каждой новой статьи ищем URL изображения.
- Сначала берём og:image (метаданные страницы), затем figure/основной блок article.
- Выбираем максимум одну подходящую картинку для каждой НОВОЙ новости.
- Пропускаем SVG/GIF/иконки/баннеры, слишком маленькие картинки и неподдерживаемые файлы.
- Поддержка JPEG, PNG, WebP; проверка размеров и ограничения скачивания (10 МБ).
- Не загружаем изображения с localhost и адресов локальной сети, HTTPS проверяется.
- Файлы сохраняем в data/news_images, в news_images записываем локальный путь, URL, размеры, хеш, подпись/авторство (если доступны). rights_status всегда unknown, пока не подтверждены законные права.
- При сбое загрузки статья по-прежнему сохраняется БЕЗ картинки.
- Старые 121 новости автоматически не скачиваются повторно. Для них нужен отдельный последующий backfill.
- Публикация изображений в MAX и Telegram-модерация пока НЕ реализованы.
- Полная модерация обязательна; MAX_PUBLISHING_ENABLED=false неизменно.

## Что обновить локально

~~~powershell
cd D:\Projects\news_aggregation
git status
git pull --ff-only
~~~

Если git status сообщает о незакоммиченных изменениях, сначала сохраните их отдельно.
Для SQLAlchemy 2.1.8 не требуется новая бинарная зависимость: извлечение
картинок использует существующие requests, BeautifulSoup и стандартную библиотеку.

## Тестирование без изменения PostgreSQL

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_news_images.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_news_image_repository.py" -v
~~~

Ожидается 6 + 3 = 9 тестов OK. Тесты используют mock сетевых запросов и
временную SQLite-базу. Реальные публикации не отправляются.

## Проверка изображений с одного сайта

~~~powershell
.\.venv\Scripts\python.exe scripts\check_news_images.py --source "НедраДВ" --limit 2
~~~

Команда только собирает статьи и показывает URL кандидатов; не изменяет БД.

Чтобы **скачать** картинки в локальную папку (без записей в БД), используйте:

~~~powershell
.\.venv\Scripts\python.exe scripts\check_news_images.py --source "НедраДВ" --limit 2 --download
~~~

Тест со сторонним сайтом ограничен доступностью самого источника. При ошибке TLS
НЕ используйте verify=False: настройте truststore или NEWS_CA_BUNDLE.

## Включение в обычном сборе (только после проверки)

Добавьте в локальный .env (файл никогда не загружать на GitHub):

~~~dotenv
NEWS_IMAGES_ENABLED=true
NEWS_IMAGE_STORAGE_DIR=data/news_images
MAX_PUBLISHING_ENABLED=false
~~~

Теперь стандартная команда обработки:

~~~powershell
.\.venv\Scripts\python.exe main.py
~~~

будет сохранять одно изображение при добавлении **каждой новой принятой статьи**.
Если файл скачать не удалось, сохраняется только текст.
Этот запуск обрабатывает и записывает новости/кластеры/сводки/теги;
это НЕ read-only проверка. Он по-прежнему НЕ отправляет в MAX.

Контроль реальных изображений и прав будет частью следующей Telegram-модерации.
На данном этапе файл может быть скачан, но не разрешён к повторной публикации.

## Ограничения этой версии

- Подбор по CMS-метаданным и HTML может выбрать неподходящую фотографию.
- JPEG/PNG/WebP проверяются по заголовку, типу и размерам; полная проверка
  визуального содержимого и авторских прав требует модерации.
- Текущий downloader дополнительно проверяет DNS и блокирует частные IP;
  в сложных инфраструктурах с DNS rebinding или прокси потребуется более
  строгая изоляция внешних загрузок.
- Источники с заблокированной HTML-страницей могут не дать фото.
- Поиск выполняется для новых статей, которых ещё нет в БД. Для ранее
  сохранённых статей сделаем отдельную безопасную дозагрузку.
