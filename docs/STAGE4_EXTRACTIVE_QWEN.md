# Этап 4 — экстрактивная суммаризация с Qwen

## Что изменилось

**Включён отдельный строгий экстрактивный режим.** Старый экспериментальный код Qwen → Gemma оставлен в истории и не используется этим режимом. Этапы 1–3, PostgreSQL и MAX не меняются.

1. Python разбивает оригинальные статьи на предложения и сохраняет точные позиции начала и конца каждого фрагмента.
2. Qwen 3.5 9B получает только ограниченный набор исходных предложений с их идентификаторами и выбирает важнейшие, **не создавая текста**.
3. Ответ нейросети — JSON со списком идентификаторов. Python извлекает оригинальные предложения по индексам и соединяет их через пробел. **Ни одно слово исходного предложения не изменяется моделью.**
4. Программная проверка подтверждает, что каждое итоговое предложение является точной подстрокой указанной исходной статьи; подмена идентификатора и добавление отдельного сгенерированного текста запрещены.
5. Gemma в этом режиме **отключена**, поскольку литературная редактура снова сделала бы сводку абстрактивной.

Сводка может сохранять местоимения и лишние вводные слова источника; при экстракции без редактуры это ограничение метода. Для сохранения фактического контекста система предпочитает цельные предложения. Максимум 5 предложений, 850 знаков (превышение отправляется модератору, не обрезается). Если модель выбирает предложения из нескольких источников, запись также направляется на ручную проверку.

Qwen вызывает Ollama локально на 127.0.0.1. Один запрос на событие и не более одного технического повтора при сломанном JSON. В этой схеме **нет ни перефразирования, ни генерации фактических утверждений**. Но факт того, что фраза взята из источника, не подтверждает истинность самого источника и достаточность контекста.

Внимание: путь к holdout_manifest.json здесь является примером; используйте существующий файл в формате Stage-4 JSON, где есть clusters, cluster_id и source_materials. Для повторного прогона старых 86 событий подойдёт тот же манифест, что был использован для Qwen + Gemma.

Нужна **только** модель qwen3.5:9b-q4_K_M, установка Gemma не требуется.

## Отчёты

В collector_test_results/stage4_extractive_v1_1/ появятся:
- stage4_extractive_results.json — текст каждой экстрактивной сводки, номера предложений, источник, URL, позиции в исходном тексте, хеши источников и статусы.
- stage4_extractive_quality_report.json — число готовых к модерации событий, ошибки выбора, статистика, встроенные офлайн-тесты.

Сохранение атомарное после каждого кластера, повторы с неизменным исходником пропускают завершённые записи. Изменённый входной манифест требует новый --out-dir. Результаты старого абстрактивного режима остаются нетронутыми.

## Ограничения и приёмка

- ready_for_moderation означает только, что выбранные фразы проверены на точное происхождение и не вызвали формальных замечаний. Не означает публикацию или человеческую проверку.
- needs_manual_review — результат подлежит проверке (например, несколько источников, слишком длинно или модель указала сомнение).
- processing_error — локальный технический сбой Ollama.
- not_for_publication — отсутствует достаточный исходный текст.

Генерация текста или дописывание фактов моделью в экстрактивном режиме запрещены. Известные ошибки абстрактивного варианта (подмена прокурора судом, несохранение статусов план/факт, числовые расхождения при редактуре) здесь не возникают **по причине перефразирования моделью**, но могут уже присутствовать в исходной публикации или проявиться из-за отсутствующего контекста. Перед публикацией в MAX сохраняется ручное одобрение.

Тесты GitHub Actions проверяют код без реального Ollama и GPU; для реального качества выбора предложений нужен запуск на локальной модели.
