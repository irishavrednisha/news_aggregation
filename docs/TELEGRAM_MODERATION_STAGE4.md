# Этап 4 — Telegram-модерация (первый рабочий вариант)

**Режим: 100% человеческая модерация.** MAX полностью выключен.
Ранее успешно выполненная миграция 20261112_01 уже создала все таблицы.
**Новая миграция не нужна.**

## Что уже реализовано

- Очередь модерации: кластеры со статусом ready, сводкой и тегами
  сохраняются как Post(status=draft) и ModerationItem(status=pending).
- Зафиксированный текст: заголовок, сводка, ссылка на источник и теги.
- Существующая одна главная фотография, если скачана, показывается
  отдельно в Telegram. Нет фото — показывается только текст.
- /id показывает собственный Telegram ID, /queue создаёт и отправляет
  до 10 карточек, /status показывает распределение статусов.
- Кнопки одобрения, отклонения, удаления фото и подтверждения прав.
- Только ID модераторов из TELEGRAM_ADMIN_IDS, только личный чат.
- Решения и идентификатор модератора сохраняются в moderation_actions.
- Проверка SHA-256 текста и выбранного image_id перед одобрением и в
  модуле MAX; повторные одобрения заблокированы.
- Публикация в MAX без реальной записи Telegram-модерации запрещена.
- Пока MAX умеет отправлять только текст; одобренные материалы с фото
  не будут отправляться до реализации отправки фото в MAX.

На этом этапе **не реализованы** редактирование заголовка/тегов через
Telegram, перегенерация сводки, подтверждение доставки MAX и
автоматическое согласование прав на фото. Поэтому MAX остаётся выключенным.

## Запуск на Windows

В каталоге D:\Projects\news_aggregation:

~~~powershell
git status
git pull --ff-only

.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_telegram_moderation.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_publisher_safety.py" -v
~~~

Для Telegram-бота мы используем уже установленный requests, без новой
библиотеки с потенциально заблокированными Windows нативными расширениями.

### Создать бота

1. Откройте в Telegram официальный @BotFather.
2. Отправьте /newbot, задайте имя и username.
3. Сохраните выданный токен только в локальном файле .env.
4. Добавьте в .env:

~~~dotenv
TELEGRAM_BOT_TOKEN=xxxxxxxxx:xxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_ADMIN_IDS=123456789
MAX_PUBLISHING_ENABLED=false
~~~

Вместо ID укажите ваш реальный Telegram ID. Чтобы узнать его безопасно:

1. Первоначально укажите в .env только токен и временный локальный
   TELEGRAM_ADMIN_IDS=1.
2. Запустите бота и отправьте /id ему в личных сообщениях.
3. Остановите Ctrl+C, впишите выведенный ID вместо 1 и запустите снова.
4. НЕ присылайте токен в чат, не коммитьте .env.

### Запуск бота

~~~powershell
.\.venv\Scripts\python.exe -m moderation.bot
~~~

В личной переписке с ботом:

- /start — информация;
- /queue — подготовить до 15 новых черновиков и отправить до 10
  ещё не отправленных карточек;
- /status — статистика;
- /id — узнать свой Telegram ID.

Одобрение и отклонение меняют только PostgreSQL. MAX при этом не
отправляет ничего: прямой вызов публикации из main.py ранее удалён.

Если карточка с картинкой, сначала оцените соответствие фото событию
и законность повторной публикации. Если прав нет или они неясны,
нажмите «Убрать фото». «Права проверены» означает: вы самостоятельно
проверили разрешение на повторное использование фото.

## Работа с реальными картинками

Пока NEWS_IMAGES_ENABLED=false, фото будет отсутствовать в новых карточках.
Можно отдельно протестировать на 1–2 статьях источника, где реально есть фото,
с помощью scripts/check_news_images.py; затем включить скачивание
для новых статей:

~~~dotenv
NEWS_IMAGES_ENABLED=true
NEWS_IMAGE_STORAGE_DIR=data/news_images
~~~

Не включайте автоматическую публикацию в MAX.

## Безопасность и ограничения

- Telegram Bot API используется по HTTPS, TLS не отключается.
- Telegram-токен не пишется в лог и не должен попадать в GitHub.
- Бот должен запускаться в ОДНОМ экземпляре, иначе несколько polling
  процессов могут конкурировать.
- Очередь формируется по нажатию /queue, а не на каждом запуске main.py.
- Карточка может остаться на стороне Telegram, если после отправки
  произошёл сбой сохранения ID. Повторное нажатие всё равно
  контролируется статусами PostgreSQL.
- При изменении текста после одобрения сверка SHA блокирует публикацию.
- Старые публикации с status=approved без записанного модератора
  в MAX больше не допускаются.
- Редактирование и перегенерацию реализуем после проверки базовых кнопок.

Если все тесты OK, покажите вывод /status и /queue (без токена). Тогда
можно переходить к редактору и поддержке отправки фото в MAX.
