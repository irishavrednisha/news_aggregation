# Первичная фильтрация промышленных новостей

Сбор остаётся независим от отбора: \`check_news_collection.py\` сохраняет **все**
успешно извлечённые статьи, чтобы были видны ложные срабатывания фильтра.
Рабочий \`main.py\` вызывает \`processing.topic_filter.filter_articles()\`
**до записи в PostgreSQL**, затем выполняются кластеризация, суммаризация
и тегирование.

## Правила первичного отбора

1. Отклоняются пустые заголовки и URL, навигационные разделы, тексты короче
   250 символов, HTML с множеством служебных элементов.
2. Событие с известной датой публикации не должно быть старше
   **30 календарных дней** по UTC. Дату публикации оцениваем по дню,
   часы/минуты не важны. Неизвестная дата **не блокирует** публикацию.
   Дата в будущем более чем на день также отклоняется.
3. По заголовку отсеиваются **однозначные** потребительские акции,
   котировки акций, корпоративные уставы, награды за социальную деятельность,
   массовые развлекательные мероприятия, студенческие визиты, внутренние
   совещания и сугубо потребительские цены.
4. Зарубежная фабричная новость без российской связи отклоняется только
   при очевидно зарубежном заголовке и отсутствии российских организаций
   в начале текста. Российскую разработку для Узбекистана или Китая
   не считаем зарубежной нерелевантной новостью.

**Нельзя** отбрасывать промышленную статью только потому, что в ней
упомянуты «выставка», «музей», «дивиденды», «вакансии», «видео»,
«зарубежный» или «Китай». В \`tagger.py\` старая проверка любого
стоп-слова по полному тексту заменена консервативной проверкой заголовка.

## Настройка свежести

В рабочей среде:
\`\`\`powershell
$env:NEWS_MAX_AGE_DAYS = "30"
python main.py
\`\`\`

Для отключения ограничения на время ручной диагностики:
\`\`\`powershell
$env:NEWS_MAX_AGE_DAYS = "0"
\`\`\`

Для конкретного аудита готового JSON (без запуска PostgreSQL и MAX):
\`\`\`powershell
python check_news_filter.py collector_test_results/news_fixed_20261106_223822.json --date 2026-11-06 --max-age-days 30 --show-kept
\`\`\`

Скрипт показывает каждое отклонение и машинный код причины
(\`stale_article\`, \`offtopic_financial_markets\`, \`navigation_page\`,
\`foreign_without_russian_connection\` и другие). Он не изменяет
входной JSON.

## Границы и дальнейшая проверка

Это **осторожный первый этап**, не полноценная семантическая классификация.
Неоднозначные статьи остаются для тегирования кластера, поэтому
в выборке могут оставаться отраслевые конференции, вопросы регулирования
и экономические материалы. Порог 30 дней — отправная точка, а не
подтверждённый оптимум. Для планирования недельного дайджеста можно
использовать 7 дней; проверять качество нужно на размеченных новостях.

Важно: если сайт регулярно отдаёт старые новости сверху, первичный
фильтр их отклонит, но **сборщик всё равно может не дойти до свежих**,
потому что его лимит \`limit_per_source\` применяется до фильтра.
Это отдельная задача отбора кандидатов, не исправляемая тем же фильтром.

Не используйте \`--allow-unverified-tls\` для автоматической публикации
новостей с сайтов, подлинность сертификатов которых не подтверждена.
