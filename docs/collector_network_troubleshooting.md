# Проверка внешних новостных источников

Проверки не записывают новости в PostgreSQL и не публикуют материалы в MAX.

## Быстрый прогон только 4 проблемных источников

Открой PowerShell в корне проекта на ветке
\`fix/site-specific-news-collection-2026-11-06\`:

\`\`\`powershell
git pull --ff-only
python -m pip install truststore
python -m unittest discover -s tests -p "test_collector_regressions.py" -v

python check_news_collection.py --source "Ростех" --source "Роснефть" --source "Промышленный вестник / ПВ.РФ" --source "Производства.рф" --limit 5 --dump-html
\`\`\`

Файлы \`collector_test_results/news_fixed_*.json\` и
\`collector_test_results/collector_html_*.zip\` позволяют отличать:
- пустую ленту,
- ошибку подключения,
- отсутствие ссылок в HTML,
- ошибку извлечения полного текста.

## Временный аналог «Всё равно перейти» (только тест)

Если в Windows установленному сайту не доверяют, но пользователь хочет
проверить, извлекаются ли из него новости, можно использовать **явный флаг**
\`--allow-unverified-tls\` в **read-only** скрипте \`check_news_collection.py\`.

\`\`\`powershell
python check_news_collection.py --source "Ростех" --source "Роснефть" --limit 5 --allow-unverified-tls
\`\`\`

При таком запуске **только** для \`rostec.ru\`, \`www.rostec.ru\`,
\`rosneft.ru\`, \`www.rosneft.ru\` и \`limited.rosneft.ru\` запрос идёт через
изолированный контекст Chromium с \`ignore_https_errors=True\`.
Сертификат Минцифры устанавливать в Windows не нужно. У других сайтов
проверка остаётся обязательной. При запуске без флага HTTPS проверяется
как раньше. Полученные новости в JSON маркируются
\`"unverified_tls": true\`.

**Важно:** это эквивалент перехода на страницу с недоверенным сертификатом,
а не способ убедиться в её подлинности. Содержимое может быть подменено
сетевым посредником. Тестовый скрипт не записывает новости в БД и не
публикует их в MAX; автоматически публиковать материалы, собранные с
отключённой проверкой, нельзя без отдельной проверки источника.

## Ростех и Роснефть: TLS

В предыдущем логе было \`CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain\`.
Это означает, что Python не смог подтвердить подлинность сертификата.
Запрещено автоматически отключать \`verify\`.

- На Windows сборщик автоматически использует системные доверенные корни,
  если установлен пакет \`truststore\`.
- Для доверенного корпоративного корневого сертификата в формате PEM
  можно **явно** указать путь к файлу:
  \`\`\`powershell
  $env:NEWS_CA_BUNDLE = "C:\path\to\trusted-ca.pem"
  python check_news_collection.py --source "Ростех" --source "Роснефть" --limit 5 --dump-html
  \`\`\`
  Добавляй сертификат только после проверки его происхождения.
- Если SSL-ошибка сохраняется, проверь доверие к HTTPS-сертификату через
  браузер, системное время, прокси и VPN. Не устанавливай чужой сертификат
  без проверки и не используй \`verify=False\`.

Для Роснефти сборщик дополнительно пробует официальный облегчённый
поддомен \`limited.rosneft.ru\` с тем же путём. В PostgreSQL при этом
остаётся URL основного домена; при доступности двух хостов дублей не будет.

## ПВ.РФ: тайм-аут

Исходный \`promvest.info/ru/novosti-promyishlennosti/\` работает
при внешней проверке, но с компьютера пользователя возвращал
\`ReadTimeout\`. Сборщик делает до двух ограниченных по времени
запросов и пытается взять новости с главной страницы того же сайта,
не переходя к случайным сторонним ресурсам.

## Производства.рф: неисправность сайта

В сохранённых HTML двух страниц был текст:
\`Error establishing a database connection\`.

Это ошибка серверной базы данных владельца сайта, которую
нельзя исправить локальными CSS-селекторами.
При временном восстановлении сайта сборщик снова сможет собирать
публикации; до этого логируется сообщение о сбое сайта.

3. Тесты \`test_collector_regressions.py\`.
