# Этап 4 — независимая оценка Qwen на новых промышленных новостях

План испытаний, а **не готовый положительный результат**. Одинаковые
41 новости, использованные при создании детерминированных правил, не
считаются независимыми. До реального запуска локального сборщика, Qwen
и слепой разметки заявлять точность нельзя.

## Что внесено

* Исправлено разбиение русских предложений: «Красногорский завод
  им. С. А. Зверева ...» не превращается в утверждения «С.» и «А.».
  Изменение действует на исходные цитаты, claims, проверки длины
  и остальные компоненты, использующие `abstractive_validator.sentences`.
* `scripts/stage4_fresh_qwen_eval.py` — строгая последовательность
  **collect → generate → score** с отдельными артефактами и защитой
  от повторного попадания прежних статей.
* Источники: полные HTML-статьи с подтверждёнными датами, не RSS
  превью. Источники из текущего набора коллектора/БД. В БД
  читаются кластеры Stage 3; **новые группировки по похожим
  заголовкам алгоритм не выдумывает**.
* Минимум **40** реальных промышленных событий с **5**
  многодокументными кластерами, в которых представлены **не менее
  двух независимых источников**. Числа должны быть подтверждены
  редактором; структурного количества недостаточно.
* Негативные примеры (служебный текст, каталоги, прошлые события)
  сохраняются в отчёте о фильтрации и для анализа ошибок,
  но не считаются положительными профильными событиями.
* Без подтверждения минимумов генерация не запускается.
  Даже если Qwen дал статус `summary_draft`, это только
  машинный предварительный статус.

## Команды на Windows 11

Из `D:\Projects\news_aggregation`:

```powershell
git fetch origin
git switch feat/stage4-independent-evaluation-2026-11-21
git pull --ff-only

.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py collect `
  --exclude collector_test_results\qwen_vs_gemma_41_mixed.json `
  --exclude collector_test_results\stage4_abstractive_v5_100.json `
  --out-dir collector_test_results\stage4_fresh_holdout `
  --mode both --target 100 --minimum 40 `
  --min-multisource 5 --max-age-days 30 `
  --limit-per-source 15 --max-per-source 15
```

Указывай в `--exclude` **все** ранее использованные Stage 4 отчёты
с `stage: 4` и полем `clusters[].source_materials` по мере
наличия. Файлы перечислены как пример прежних путей: если файл
на диске носит иное имя, передай реальный путь. Если старого отчёта
нет, не исключай его «по памяти»: для полноценной независимости
нужны данные исходных статей.

При успехе `collect` запиши хеш входного манифеста, не меняй
`holdout_manifest.json` после заморозки выборки.

Затем — только при прохождении набора порогов:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py generate `
  --out-dir collector_test_results\stage4_fresh_holdout
```

Вызовы идут в локальный Ollama через Qwen3.5 9B Q4_K_M.
При обрыве модельного вызова повтори `generate` с `--resume`.
Только после полного прогона программа создаст:

- `qwen_holdout.json` — проверяемые сводки и автоматические статусы;
- `blind_qwen_review.jsonl` — тексты источников и сводки
  **без автоматического решения и флагов**;
- `qwen_review_labels.csv` — лист ручной разметки;
- `private_qwen_review_key.json` — закрытая привязка ID к статусам
  модели (не показывай её разметчику).

Рецензент читает каждый исходный документ и независимо отмечает
`pass`/`fail` для `faithful_facts`, `natural_russian`,
`main_event_covered`, `meaningful_news_event`, `source_quality`.
Для многодокументных событий он проверяет также
`event_coherence`: все ли материалы **одного события**.
Для одноисточниковых материалов `event_coherence=na`.
Для пустой сводки: все поля `na`.
В `error_details` укажи конкретную ошибку с цитатой, а не
автоматическое пояснение модели.

После ручной разметки:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py score `
  --out-dir collector_test_results\stage4_fresh_holdout
```

Результат `qwen_human_score.json` содержит число правильно
принятых, ложно принятых и ошибочно направленных на review сводок,
интервал Уилсона для доли качественных автоматических черновиков.
`independent_evaluation_complete=true` **только когда** все
существующие сводки размечены, вручную подтверждены не менее 40
профильных событий и не менее пяти многодокументных событий.

Если `collect` сообщает недостаточно реальных кросс-источниковых
кластеров, это **недостаток эмпирических данных**, а не повод
генерировать искусственные пары. Нужно собрать больше дней
или добавить новые реально подтверждённые кластеры Stage 3 на
**копии** базы, не менять продакшен-события и не отключать TLS.


### Быстрый режим без двух отдельных запусков

Если нужен единый запуск сбора и локальной Qwen-генерации, вместо
`collect` и `generate` используй подкоманду `run` с теми же
аргументами:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py run `
  --exclude collector_test_results\qwen_vs_gemma_41_mixed.json `
  --exclude collector_test_results\stage4_abstractive_v5_100.json `
  --out-dir collector_test_results\stage4_fresh_holdout `
  --mode both --target 100 --minimum 40 --min-multisource 5
```

Если наберётся меньше 40 реальных свежих событий или меньше пяти
многодокументных групп, команда сохранит диагностический манифест,
**не вызвав Qwen**. После возобновления окружения можно повторить
ровно эту команду с `--resume`, при том же наборе прежних исключений.
Ручную разметку и `score` эта команда **не имитирует**.

## Ограничения

Офлайн unit-тесты используют синтетические фикстуры и **не считаются
новыми реальными новостями**. Независимость зависит от полного списка
старых исключений и проверки событийной идентичности. Никакая
положительная оценка не переводит результаты автоматически в MAX
или одобрение публикации.


## Случай 90 новых статей, 0 многодокументных групп

Реальный локальный сбор 20.11.2026 отобрал 90 датированных HTML-статей,
но каждая пришла отдельной группой. Поэтому `qwen_holdout_gate.json`
честно записал `fewer_than_required_multi_document_events`.
Результат не означает, что за один день нет одинаковых событий:
источники содержали четыре очевидных кандидата на общие события:

- `900002` + `900017` — конвейерный комплекс Ковдорского ГОКа;
- `900010` + `900038` — центр переработки ядерного топлива Росатома;
- `900015` + `900033` — производство Хромос в Дубае;
- `900016` + `900053` — первое чтение законопроекта о золотодобыче.

Отдельно найдено ещё несколько опубликованных **по другим URL** статей
об уже присутствующих событиях: КЭАЗ, Невский завод, траулер
«Капитан Геллер», ЛиАЗ. В репозиторий сохранены **ссылки, а не
придуманные тексты/даты**. Для включения скрипт должен получить
саму страницу через текущий сборщик с проверкой TLS, найти
фактическую дату и полный HTML-текст.

Существующий **оригинальный** манифест сохраняется неизменным. Из корня
репозитория:

```powershell
git fetch origin
git switch feat/stage4-independent-evaluation-2026-11-21
git pull --ff-only

.\.venv\Scripts\python.exe scripts\stage4_reconcile_multisource.py `
  --input-manifest collector_test_results\stage4_fresh_holdout\holdout_manifest.json `
  --out-dir collector_test_results\stage4_fresh_holdout_reconciled `
  --supplemental-json docs\stage4_supplemental_articles_example.json `
  --generate
```

Параметр `--generate` вызывает Qwen **в рамках того же запуска**,
но только когда проверка после фактического извлечения страниц
подтвердила 40+ событий и 5+ многодокументных групп. Иначе
Qwen не запускается, остаётся диагностический gate.

Это создаст новые `holdout_manifest.json`,
`qwen_holdout_gate.json` и `multi_event_candidates.json` только
в каталоге `stage4_fresh_holdout_reconciled`. Сопоставление
двух источников использует отдельно близость заголовков и начал
текстов, один документ не может присоединиться к двум группам.
Для исходных 90 статей это четыре кандидатные группы
(86 уникальных событий после объединения). Никаких ложных
копий исходных текстов не создаётся.

**Важно:** similarity означает только кандидатную связь, а не
доказанную принадлежность к единому событию. Поле
`event_identity_verified=false` сохраняется, и итоговая слепая
ручная оценка `event_coherence` должна подтвердить каждый
многодокументный кластер. Если дополнительная страница недоступна,
дата отсутствует, SSL не проходит, текст слишком короткий
или событие расходится — она не присоединится и выходной
`ready_for_model_generation` останется `false`.

Если новый gate действительно содержит
`ready_for_model_generation: true` (не угадывай значение), то:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py generate `
  --out-dir collector_test_results\stage4_fresh_holdout_reconciled
```

Затем — слепая ручная разметка, а после неё:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_fresh_qwen_eval.py score `
  --out-dir collector_test_results\stage4_fresh_holdout_reconciled
```

Старый `run` для `stage4_fresh_holdout` не превращает
90 одиночных записей в 5 реальных групп автоматически. Следует
использовать **отдельный** `stage4_reconcile_multisource.py`,
не заменять исходные отчёты и не отключать TLS.
