# Этап 4 — окончательный конвейер Qwen → Gemma

## Архитектура

Новый автономный read-only конвейер продолжает `feat/stage4-independent-evaluation-2026-11-21` (PR #14). Ранее реализованные функции Qwen и Gemma не удалены. PostgreSQL, MAX, этапы 1–3 не изменяются.

1. **Qwen3.5 9B (`qwen3.5:9b-q4_K_M`)** формирует самостоятельную короткую новость. Программно сформированные цитаты, числа, субъекты, статусы, условия и причинность проверяются существующими валидаторами.
2. **Gemma 3 4B (`gemma3:4b`)** отдельно рецензирует каждое утверждение, возвращая `supported`, `contradicted` или `insufficient_evidence`, источник, дословную цитату, причину и предложение исправления. Вывод Gemma не считается истиной: проверяются цитаты и фактические отношения.
3. **Gemma** редактирует всю сводку как единый текст, а не отдельные предложения.
4. **Финальный валидатор** проверяет текст одновременно с исходниками и Qwen. Если Gemma меняет факты, используется прошедший собственную проверку Qwen, если рецензия Gemma не обнаружила существенного риска. Иначе — `needs_manual_review`.

Строго ограниченные вызовы: Qwen 1 (+ максимум 1 повтор только при технической ошибке JSON/схемы), затем 1 рецензия Gemma, 1 редактура Gemma. Без циклов генерации. Ollama работает только по loopback, `keep_alive=0` освобождает модель перед следующим запросом. Таймаут 240 с.

## Один запуск на Windows

Откройте PowerShell в `D:\Projects\news_aggregation`, переключитесь на ветку PR и убедитесь, что Ollama работает и обе модели уже установлены. Одна команда запускает офлайн-регрессии, оба локальных LLM и сохранение полного отчёта:

```powershell
.\.venv\Scripts\python.exe scripts\stage4_final_acceptance.py --input collector_test_results\holdout_manifest.json
```

Путь `--input` — **пример**. Требуется существующий Stage-4 JSON (`stage: 4`, `clusters` с `cluster_id` и `source_materials`). Если ваш файл находится в другом месте, укажите реальный путь. Запуск не собирает новую независимую выборку самостоятельно.

В папке `collector_test_results/stage4_qwen_gemma_final` появляются:

- `stage4_final_results.json`: полные исходники, хеш источников, Qwen, Gemma-фактчек, редактура Gemma, выбранный финал, замечания, статус, время и число запросов.
- `stage4_quality_report.json`: технические проверки, статистика выбора, ошибки и явно *незаполненные* человеческие метрики.

Снимок записывается атомарно после каждого события. Повторный запуск с тем же входом пропускает завершённые события. Если хеш входного файла изменился, прежний результат не перезаписывается: используйте новый `--out-dir`.

## Статусы и передача этапу 5

- `ready_for_moderation` — итог прошёл предусмотренные программные проверки, **не одобрен для публикации**.
- `needs_manual_review` — конфликт, недостаточно доказательств, сомнение или отклонённый текст.
- `not_for_publication` — нет пригодных оригиналов.
- `processing_error` — технический сбой; можно безопасно повторить.

Для будущего тэггера использовать `final_summary`, `source_ids`, `source_urls`, `main_event`, `status` и `source_sha256` из итогового JSON. Не перегенерировать сводку и не считать прохождение механических проверок доказанной фактической точностью. Публикация в MAX только после ручного одобрения.

## Приёмка

CI `.github/workflows/stage4-qwen-gemma-final.yml` запускает Python-компиляцию, регрессии интеграции и существующие проверки Qwen. Реальный локальный Ollama/GPU и новые статьи в GitHub Actions не доступны. Проверку на 86 уже изученных событиях нельзя выдавать за независимый human holdout. Для оценки фактической точности и естественности требуется отдельная новая выборка и слепая человеческая разметка; поля `human_*` останутся `null` до такой проверки.

`ready_for_stage5_data_contract` обозначает только техническую пригодность выходного JSON к следующему этапу, но не подтверждает качество журналистских новостей. У Gemma остаются обе обязательные роли. Если редактура искажает текст, завершённый безопасный режим — Gemma как рецензент, Qwen как выбранный автор, с ручной модерацией.
