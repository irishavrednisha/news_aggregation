# Экспериментальный AI-теггер новостей

## Зачем

Предыдущая реализация использовала Sentence-BERT для одной большой
строки (заголовок, summary, тело статьи, повторённые несколько раз),
косинусную близость с длинными словарями тегов, keyword boost/penalty.
Это может приводить к ложным тегам по побочным словам в тексте.

**Новый опциональный режим:** локальная мультиязычная NLI-модель
(Zero-Shot Classification). Никакого обучения на ручной выборке и платного
API не требуется. Модель **НЕ генерирует** новые названия рубрик: выводит
только имеющиеся 18 тегов \`processing.tagger.TAGS\` или пустой список.

1. Сначала оценивает, является ли главный сюжет новости промышленным
   (\`industry_score\` по двум конкурирующим гипотезам).
2. Для промышленной новости оценивает 18 тематик **независимо**
   (\`multi_label=True\`); допустимы несколько тегов.
3. Оставляет максимум 2 (настраивается) тега выше порога 0.65 и
   не более чем на 0.15 ниже лучшего тега.
4. Если нет подходящих тегов, статус \`not_for_publication\`.
   Только \`ready\` с непустыми тегами может попасть в публикацию MAX.

Важное отличие: AI анализирует заголовок + TextRank-summary + короткое
начало основной статьи **один раз без искусственного повторения заголовка**.
Название источника не используется как доказательство тематики.
Проверка связи с Россией и наличие полного текста пока сохраняются
из прежнего pipeline.

## Используемая модель

По умолчанию: \`MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli\`.
Лёгкая мультиязычная NLI-модель, подходящая для CPU и русского языка.
Более ресурсоёмкая альтернатива:
\`MoritzLaurer/mDeBERTa-v3-base-mnli-xnli\`.

Система **по умолчанию остаётся в legacy** режиме до сравнения с
реальными размеченными публикациями: нельзя автоматически включать
новый классификатор в канал без измерения качества.

## Как безопасно проверить на уже собранном JSON

На Windows, в активированном виртуальном окружении:

\`\`\`powershell
python -m pip install "transformers>=4.40,<5" torch sentencepiece

git switch fix/site-specific-news-collection-2026-11-06
git pull --ff-only

python check_ai_tagging.py collector_test_results/news_fixed_20261106_223822.json --limit 10 --output ai_tag_results.json
\`\`\`

При первом запуске модель загружается из Hugging Face в локальный кэш.
Для более глубокой выборки можно увеличить \`--limit\` до 45.
Скрипт читает JSON и печатает \`industry_score\`, теги и top-4 оценки.
Опция \`--output\` создаёт отдельный отчёт; исходный JSON остаётся
нетронутым, **PostgreSQL не меняется, публикация в MAX отсутствует**.

Важное ограничение проверки: в JSON ещё нет TextRank-summary кластеров,
поэтому тестовый скрипт использует начало статьи как его приближение.
Настоящий \`tag_cluster()\` использует \`cluster.summary_text\`.
Поэтому результаты могут различаться.

## Переключение конвейера (только после ручной проверки)

\`\`\`powershell
$env:NEWS_TAGGER_BACKEND = "nli"
$env:NEWS_AI_TAG_MIN_SCORE = "0.65"
$env:NEWS_AI_RELEVANCE_MIN_SCORE = "0.60"
$env:NEWS_AI_TAG_MODEL = "MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli"
\`\`\`

**Не запускайте \`main.py\` только ради проверки тегов**: он
автоматически публикует ready-кластеры в MAX. Используйте
\`check_ai_tagging.py\` до подтверждения качества и ручной калибровки.

Если AI-модель не загрузилась, кластер останется в статусе \`new\`
без тегов и **не будет опубликован**. Значения NLI-score нельзя
трактовать как достоверную вероятность, пороги 0.60/0.65 — гипотезы
для сравнения, не подтверждённые на русскоязычной выборке.

## Как измерить улучшение

Разметить 50–100 реальных новостей, включая сложные (финансовые рынки,
транспорт, выставка технических решений, юридические вопросы рудника),
набором эталонных рубрик или \`[]\` («не публиковать»).
Сравнить прежнюю SBERT-систему и NLI на тех же текстах по
precision/recall/F1 для тегов, доле неправильно опубликованных
и доле потерянных промышленных новостей. После тестов можно
решать, включать ли NLI по умолчанию и какой моделью пользоваться.
