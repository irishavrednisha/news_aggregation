# Экспериментальный AI-теггер новостей

## Зачем

Предыдущая реализация использовала Sentence-BERT для одной большой
строки (заголовок, summary, тело статьи, повторённые несколько раз),
косинусную близость с длинными словарями тегов, keyword boost/penalty.
Это может приводить к ложным тегам по побочным словам в тексте.

**Новый опциональный режим:** локальная мультиязычная NLI-модель
(Zero-Shot Classification). Никакого обучения на ручной выборке и платного
API не требуется. Модель **НЕ генерирует** новые названия рубрик: выводит
только имеющиеся 18 тегов \`processing.tagger.TAGS\` или пустой список.

1. Сначала определяет **главное событие**: запуск производства,
   испытания оборудования, добыча, производственные результаты,
   обучение, фестиваль, биржевые новости и другие типы событий.
   Классы конкурируют между собой (multi_label=False).
2. Для промышленного события определяет тематику из прежних 18 тегов.
   Они также конкурируют между собой (multi_label=False), чтобы
   «металлургия», «ТЭК» и «инжиниринг» не получали почти одинаково
   высокие независимые оценки в новости про обучение работников.
3. Оставляет максимум два тега с относительной оценкой не ниже 0.12.
   Второй тег обязан набрать хотя бы 60% оценки первого.
   Суммарная оценка промышленных типов событий — не менее 0.60.
4. Если нет подходящих тегов, кластер не публикуется.

**Внимание:** численные оценки v2 и v1 несопоставимы.
В v2 все классы одного этапа образуют распределение с суммой
оценок примерно 1. Значения 0.12 и 0.60 экспериментальные,
а не откалиброванные вероятности правильности.

Важное отличие: AI анализирует заголовок + TextRank-summary + короткое
начало основной статьи **один раз без искусственного повторения заголовка**.
Название источника не используется как доказательство тематики.
Проверка связи с Россией и наличие полного текста пока сохраняются
из прежнего pipeline.

## Используемая модель

По умолчанию: \`MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli\`.
Лёгкая мультиязычная NLI-модель, подходящая для CPU и русского языка.
Более ресурсоёмкая альтернатива:
\`MoritzLaurer/mDeBERTa-v3-base-mnli-xnli\`.

Система **по умолчанию остаётся в legacy** режиме до сравнения с
реальными размеченными публикациями: нельзя автоматически включать
новый классификатор в канал без измерения качества.

## Как безопасно проверить на уже собранном JSON

На Windows, в активированном виртуальном окружении:

\`\`\`powershell
python -m pip install "transformers>=4.40,<5" torch sentencepiece

git switch fix/site-specific-news-collection-2026-11-06
git pull --ff-only

python check_ai_tagging.py collector_test_results/news_fixed_20261106_223822.json --limit 45 --primary-filter --as-of 2026-11-06 --summary-mode textrank --output ai_filtered_textrank.json
\`\`\`

При первом запуске модель загружается из Hugging Face в локальный кэш.
Для более глубокой выборки можно увеличить \`--limit\` до 45.
Скрипт показывает главное событие, его оценку и ранжирование 18 отраслей.
Опция \`--output\` создаёт отдельный отчёт; исходный JSON остаётся
нетронутым, **PostgreSQL не меняется, публикация в MAX отсутствует**.

Теперь `check_ai_tagging.py` по умолчанию вычисляет тот же
TextRank-summary, что рабочий `summarize_cluster()` для **одной** новости:
заголовок + первые 2500 символов, TextRank, 4 предложения,
максимум 800 символов. Для многоновостных кластеров итоговый
summary может отличаться. Флаг `--summary-mode lead` воспроизводит
старый тест без TextRank. Флаги `--primary-filter --as-of 2026-11-06`
проверяют только новости, проходившие первый фильтр
на дату выгрузки. Работа с базой/публикацией отсутствует.

## Переключение конвейера (только после ручной проверки)

\`\`\`powershell
$env:NEWS_TAGGER_BACKEND = "nli"
$env:NEWS_AI_TAG_MIN_SCORE = "0.12"
$env:NEWS_AI_RELEVANCE_MIN_SCORE = "0.60"
$env:NEWS_AI_TAG_MODEL = "MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli"
\`\`\`

**Не запускайте \`main.py\` только ради проверки тегов**: он
автоматически публикует ready-кластеры в MAX. Используйте
\`check_ai_tagging.py\` до подтверждения качества и ручной калибровки.

Если AI-модель не загрузилась, кластер останется в статусе \`new\`
без тегов и **не будет опубликован**. Значения NLI-score нельзя
трактовать как достоверную вероятность, пороги 0.60/0.12 — гипотезы
для сравнения, не подтверждённые на русскоязычной выборке.

## Что показал первый реальный тест

В первой выборке из 10 статей старый NLI v1 выдал теги
для 6 и оставил без тегов 4. Подтверждённые проблемы:
обучение менеджеров судостроительных проектов получило
«инжиниринг» и «металлургию»; конкурс «Битва роботов» —
«инжиниринг» и «машиностроение»; модернизация ДСП
«Свезы» ошибочно получила «инжиниринг» и
«машиностроение». Двигатели ОДК не получили тегов.

Вторая версия устраняет проблемный принцип независимой оценки
всех тем и проверяет главное событие. **Но пока не доказано,
что реальная модель стала точнее:** автоматические тесты
проверяют API и переходы статусов на искусственных оценках.
Для подтверждения нужен повторный запуск на 10/45 реальных
новостях, затем сравнение по эталонной разметке.

## Первая и вторая версии на 10 реальных статьях

Отчёт первой версии: 6 из 10 статей получили теги, но среди них
были ошибочные новости про обучение руководителей ОСК и конкурс
роботов. Вторая версия с отдельным определением главного события
устранила эти три ошибочных назначения, но из-за высокого
порога 0.22 дала теги только **1 из 10**.

Сравнение сохранённых scores v2 без повторной загрузки модели
показало, что при пороге **0.12**:
- российская АЭС в Мьянме получит «атомная отрасль» и «ТЭК»
  (0.2057, 0.1362);
- модернизация производства ДСП «Свезы» получит
  «технологическое производство» и «заводы» (0.1447, 0.1422);
- модернизация «Свезы» в Мантурове сохранит два правильных тега;
- обучение, соревнование роботов, заголовок про банкротство,
  пожарные дроны и отгрузка фанеры по текущим scores
  останутся без тегов.

Таким образом, прогноз по **сохранённым** результатам v2 —
3/10 с тегами. Порог 0.18 на главную категорию события
удалён: он отсеивал сообщение о двигателях ОДК,
у которого суммарная промышленная оценка 0.743.
Однако вычисления по отраслевым тегам ОДК в прошлом прогоне
вообще не проводились; результат новой версии для него
необходимо измерить повторно. Этот прогноз не подтверждает
качество модели без проверки на реальных текстах и ручной разметки.

## Проверка на 45 статьях, NLI v2 (порог 0.12)

Отчёт `ai_tag_results_v2_45.json`: теги у **17 из 45** статей;
**28 без тегов**. Среди 21 статьи, оставленной предыдущим
первичным фильтром, теги получили **11**, ещё **10** — нет.

Подтверждённые ложные назначения самого AI-классификатора:
конкурс ОСК → «инновации, оборонная промышленность»,
цены на красную икру → «ТЭК»,
судебная передача акций завода → «машиностроение, инжиниринг».
Эти материалы могут отсеиваться до AI фильтром: это не
означает, что production обязательно опубликует их.

Пропущены профильные новости об остановке рудника
«Дальполиметалла», контроле доменных печей НТМК,
технологии извлечения лития «Гиредметом», а также
контейнерном кране речного порта.

Тип события `industrial_transport` оказался лидером в
**11/45**, включая модернизацию ДСП и другие
нетранспортные сюжеты. Это проблема самой постановки
zero-shot задачи, а не только порога 0.12.

**Ключевая оговорка:** этот отчёт получен со вступлением
из первых 780 символов статьи, а не с рабочим TextRank.
Изменён тестовый скрипт, чтобы получить более реалистичные
результаты и разбирать причины ошибок на прошедших
первичный фильтр материалах. Пока менять пороги без
размеченной выборки не следует.

## Как измерить улучшение

Разметить 50–100 реальных новостей, включая сложные (финансовые рынки,
транспорт, выставка технических решений, юридические вопросы рудника),
набором эталонных рубрик или \`[]\` («не публиковать»).
Сравнить прежнюю SBERT-систему и NLI на тех же текстах по
precision/recall/F1 для тегов, доле неправильно опубликованных
и доле потерянных промышленных новостей. После тестов можно
решать, включать ли NLI по умолчанию и какой моделью пользоваться.
