# Следующий этап: независимые REAL Validation и Test без утечки

Синтетические 4000 новостей уже преобразованы в 6700 SFT-сообщений
в training/news_sft/train.jsonl. **Не переделывайте train**.
Сейчас validation и test пустые — это нормально; нужно собрать и
проверить **другие реальные** новости.

Технические скрипты: scripts/real_news_review.py и
training/prior_eval_url_sha256_80bit.txt. Отдельная защита
исключает 125 URL из двух ранее изученных тестовых наборов
(100 + 25), даже когда пользователь не сохранил исходные файлы.
Похожие заголовки и сильно совпадающие тексты также фильтруются внутри новой партии.
Это удаляет синдицированные новости с разными заголовками, но НЕ гарантирует
отсутствие всех смысловых дублей: редактор проверяет оставшиеся сюжеты вручную.
При наличии прежних JSON для проверки похожих старых названий
можно дополнительно передать их через --exclude.

## 1. Получить новые статьи (PowerShell, D:\Projects\news_aggregation)

Оригинальный check_news_collection.py читает настройки источников
из PostgreSQL, но не записывает собранные новости и не публикует их.

    cd D:\Projects\news_aggregation
    git pull --ff-only origin fix/site-specific-news-collection-2026-11-06
    .\.venv\Scripts\python.exe check_news_collection.py --limit 20

Эта команда работает с текущими источниками. Обычно создаётся
collector_test_results\news_fixed_YYYYMMDD_HHMMSS.json.

## 2. Сделать защищённую выборку для ручной разметки

    $latest = Get-ChildItem .\collector_test_results\news_fixed_*.json | Sort-Object LastWriteTime -Descending | Select-Object -First 1 -ExpandProperty FullName
    .\.venv\Scripts\python.exe -m scripts.real_news_review prepare --news "$latest" --out training\real_review --max 120 --per-source 15

**Важно:** повторный `prepare` в ту же папку теперь остановится,
чтобы не стереть заполненный `review_sheet.csv`. Для нескольких свежих
сборов *до начала разметки* передайте все JSON одной командой:

    $allNews = @(Get-ChildItem .\\collector_test_results\\news_fixed_*.json | Sort-Object LastWriteTime -Descending | Select-Object -ExpandProperty FullName)
    .\\.venv\\Scripts\\python.exe -m scripts.real_news_review prepare --news $allNews --out training\\real_review --max 120 --per-source 15

Если разметка уже началась, сохраните текущую папку и для новой партии
укажите другой `--out`. Не запускайте `finalize` для нескольких папок
поочерёдно в один `--output-dir`: он перезаписывает validation/test.

Если в рабочей папке есть обе старые выборки, добавьте:
    --exclude tagging_benchmark_100.json --exclude tagging_fresh_25.json

Это позволит исключать также статьи с почти совпадающими
заголовками относительно старых выборок (встроенный файл
уже исключает 125 URL и без этих дополнительных аргументов).

Результат:
- training/real_review/source_index.json — полный исходный текст,
  назначенная заранее группа validation/test, URL, источник, дата;
- training/real_review/review_sheet.csv — лист разметки (UTF-8 BOM,
  разделитель точка с запятой; удобно открыть в Excel).

Если candidates=0, это НЕ ошибка: все найденные новости уже были
в прежних 125 URL, были слишком короткими или не прошли фильтры.
Подождите новых публикаций или соберите больше источников.
НЕ снимайте исключение старых URL, чтобы получить красивый тест.

## 3. Ручная проверка статей

Сначала проверьте полный текст из source_index.json.
Нельзя доверять автоматически предлагаемым моделью меткам:
для независимого контроля оценку устанавливает редактор.

Для каждой строки CSV (разделитель «;») заполните:
- review_status = verified (строго после фактической проверки);
- relevant = yes / no;
- tags = точные имена допустимых категорий через вертикальную черту,
  например: машиностроение|инжиниринг. Не более двух;
- evidence_1 ... evidence_5 = ДОСЛОВНЫЕ фрагменты статьи
  длиной 15–350 символов каждый, подтверждающие сводку;
- summary = 2–3 новых русских предложения своими словами, обычно
  250–400 символов, можно 100–249 при малом объёме фактов,
  максимум 550; не выдумывайте утверждения;
- notes = примечания о сомнительных сведениях.

При relevant=no оставьте tags/evidence/summary пустыми.
При сомнениях оставьте review_status=draft: такой пример
не попадёт в оценку.

Не заменяйте exact evidence пересказом. Не утверждайте, что
исторические инвестиции относятся к новому проекту, либо
что запланированное событие уже произошло.

**Главное:** не допускать одни и те же сюжеты в validation и test.
Скрипт убирает похожие заголовки, но тематические дубли с
другими названиями нужно найти редактору. При обнаружении
таких дублей оставьте спорные строки draft. Не добавляйте
полученные validation/test статьи в обучающий train.

## 4. Сборка после проверки

    .\.venv\Scripts\python.exe -m scripts.real_news_review finalize --review-dir training\real_review --output-dir training\news_sft

Файлы:
- training/news_sft/validation.jsonl — только real+verified;
- training/news_sft/test.jsonl — только real+verified;
- training/news_sft/real_gold_verified.json — проверенные исходные
  примеры для воспроизводимости.

Важно: 6700 сообщений в training/news_sft/train.jsonl НЕ
перезаписываются. Если строки остались draft, они не попадут
в validation/test. Ошибка в разметке останавливает сборку,
и скрипт укажет строку CSV. Test сохраняйте для финальной
оценки, не подбирайте по нему модель.

Для первого обучения желательно >=20 real validation сообщений
(это не 20 статей: профильная статья даёт две SFT-задачи).
Для более достоверного сравнения стремитесь к 50–100
разнообразным реальным статьям и достаточному числу в test.
Не фиксируйте лучший результат по 25 прежним экспериментам.

## 5. Подготовка компьютера к обучению (позже)

На ПК RTX 5060 Ti 8 ГБ и RAM 16 ГБ, WSL2 ещё не установлен.
После подготовки качественной разметки можно проверить
размещение WSL2 на диске с достаточным свободным местом,
установить Ubuntu и отдельное Python-окружение для LoRA.
Не устанавливайте обучение в рабочую .venv сборщика.
Перед запуском сначала:

    python -m scripts.train_news_lora --model unsloth/Qwen3.5-2B --data-dir training/news_sft

По умолчанию это DRY RUN без --run.
Ни один из скриптов real_news_review не вызывает MAX,
Ollama, модельное обучение или изменение PostgreSQL.
