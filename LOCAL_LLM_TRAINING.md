# Локальная модель для промышленных новостей: теги + собственная сводка

## Цель

Вместо TextRank и сочетания SBERT/regex — локальная языковая модель,
которая сама выделяет главное событие, классифицирует по 18 тематикам
и пишет краткую абстрактивную сводку **своими словами**.

Прототип: Qwen3.5-4B (Apache 2.0) через Ollama. Его ещё не обучали,
а рабочий процесс и публикацию в MAX не меняли.

На данный момент скрипт делает ДВА вызова локальной модели:
1. Определяет релевантность и теги, извлекает дословные подтверждающие
   фрагменты из исходного текста.
2. Пишет 2–3 новых предложения только по этим фрагментам.

### Длина сводки для MAX

- Обычная промышленная новость: **250–400 символов с пробелами**.
- Если фактов немного: **150–250 символов**, без искусственного растягивания.
- Если много важных подтверждённых деталей: **400–550 символов**.
- **550 символов — жёсткий максимум**, считается только тело `summary`,
  без заголовка, тегов и ссылки.

Длина 250–400 — ориентир для генерации, не обязательный минимум:
корректная сводка может быть короче. Система сохраняет 2–3
предложения своими словами.

Проверка на первых 5 реальных статьях (3 профильные) после изменения
целевой длины дала **223, 196 и 137 символов**, поэтому одного
промпта о длине оказалось недостаточно. Следующий вариант улучшает
**полноту извлечения фактов**: LLM по возможности выбирает 3–5
разных подтверждающих цитат (главное событие, изделие, техническую
деталь, результат, цифры), вместо минимальных двух.
Не выдумывать детали ради числа цитат или символов.
Отдельно предписано сохранять оговорки о приблизительных величинах
и не приписывать изготовление организации без явного основания.

После этого изменения повторный локальный прогон ещё не выполнялся.
Указанные 5 статей уже служат материалом разработки, а не
независимой контрольной выборкой. Тестовый локальный обработчик проверяет
факты-цитаты, новые числа и почти дословное копирование исходных
предложений. Слишком длинную или почти дословную сводку отправляет
на **одну повторную генерацию**. Если вторая версия по-прежнему
превышает 550 символов, она не возвращается как готовая сводка:
`summary=""`, предупреждение `summary_discarded_too_long`.
Автоматическая публикация пока не подключена.

В генераторе синтетических обучающих новостей используется та же
политика длины; примеры больше 550 символов не принимаются
в тренировочные пары. Не обрезать предложения механически:
так можно потерять важный факт.


Фрагменты проверяются на наличие в источнике, а числа в сводке —
на наличие в подтверждающих фрагментах. Это не устраняет все
галлюцинации. В экспериментальном режиме остаётся обязательная
проверка перед публикацией.

## Запустить без обучения и без MAX

Скачать Ollama с https://ollama.com/download/windows и запустить её.

PowerShell (из корня проекта):

    git pull --ff-only origin fix/site-specific-news-collection-2026-11-06
    ollama pull qwen3.5:4b
    .\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_local_news_llm.py" -v
    .\.venv\Scripts\python.exe check_local_news_llm.py tagging_fresh_25.json --limit 5 --model qwen3.5:4b --output collector_test_results/llm_fresh5_preview.json

Адрес модели жёстко ограничен 127.0.0.1:11434. Режим cloud запрещён.
Не включено обращение к базе или MAX.

## Генерация большой синтетической выборки

    .\.venv\Scripts\python.exe -m scripts.generate_news_training_synthetic --per-tag 100 --negatives 1500 --model qwen3.5:4b --output training/synthetic_candidates.json

Это до 3300 вымышленных тренировочных новостей: по 100 для каждого
из 18 тегов и 1500 непрофильных. Можно увеличить объём, но
не количество само по себе определяет качество. Модель-учитель
должна быть сильной; желательно проверить с Qwen3.5-9B при наличии
аппаратных ресурсов. Генератор сохраняет каждый результат для
возобновления работы.

Все эти примеры являются вымышленными. Пометка auto_checked означает
ТОЛЬКО проверку цитат и чисел, не проверку смысла. Нужно вручную
проверять репрезентативную часть каждой темы, чтобы выявить
систематические ошибки модели-учителя.

## Подготовка SFT датасета

Вход — локальный JSON с массивом examples. Поля каждой записи:
story_id, origin (synthetic/real), split (train/validation/test),
review_status (verified/auto_checked/draft), title, text, relevant,
tags, evidence (дословные фрагменты), summary (своя сводка).

Для непрофильных: relevant=false, tags=[], evidence=[], summary="".
Примеры с draft в обучение не включаются. Для синтетики с
auto_checked требуется ЯВНО включить оба параметра:

    .\.venv\Scripts\python.exe -m scripts.build_news_sft training\news_examples.json --allow-synthetic --allow-auto-checked-synthetic --output-dir training/news_sft

Синтетика допускается только в train, реальные проверенные примеры
нужны для независимой validation и test. Сюжеты одного события
никогда не должны пересекать train и тест. Старые 100 и новые 25
статей с предварительными draft-метками не являются проверенным
эталоном. Файл synthetic_candidates.json может быть частью
news_examples.json, но он НЕ содержит реальные validation/test.

## Рекомендация для RTX 5060 Ti 8 ГБ / RAM 16 ГБ (08.11.2026)

- Для локального inference используй qwen3.5:4b (примерно 3.3–4.0 ГБ
  квантованных весов плюс дополнительная память под контекст).
- Для обучения здесь выбрана **Qwen3.5-2B bf16 LoRA**. В Unsloth
  ориентир — около 5 ГБ VRAM, у Qwen3.5-4B ~10 ГБ.
  Из 8 ГБ сейчас ~1.2 ГБ занято Windows/графическими процессами,
  поэтому 4B bf16 LoRA на этой GPU не рекомендуется.
- Скрипт train_news_lora.py по умолчанию теперь выбирает
  unsloth/Qwen3.5-2B, max_seq_length=1024,
  batch_size=1, gradient_accumulation_steps=4. Обучение запускается
  ТОЛЬКО с --run и при наличии verified real validation.
- Нельзя запускать обучаемую модель и Ollama одновременно, если
  обе размещаются на GPU. Закрой игры, проверь nvidia-smi.
- Рекомендуемый путь обучения — WSL2 Ubuntu с отдельным Python
  окружением. Команды в PowerShell для проверки наличия WSL2:

      wsl --status
      wsl -l -v

  Если WSL ещё не установлен, сначала проверь доступное место
  и сделай резервную копию важных данных. Для установки обычно
  используют `wsl --install -d Ubuntu` из PowerShell
  администратора; может потребоваться перезапуск.
  Windows-драйвер NVIDIA остаётся установленным в Windows.
- Уменьшение max_seq_length до 768 и закрытие GPU-приложений может
  помочь при нехватке VRAM. Нельзя сокращать реальную статью так,
  чтобы пропала суть события: отмечай обрезанные примеры.

## Дообучение LoRA

Qwen3.5 лучше обучать в bf16 LoRA: Unsloth предупреждает о
проблемах с 4-битной QLoRA для этого семейства. Ориентиры VRAM:
Qwen3.5-2B ~5 ГБ, Qwen3.5-4B ~10 ГБ, Qwen3.5-9B ~22 ГБ
(может потребоваться больше памяти).

Официальный гайд: https://unsloth.ai/docs/models/qwen3.5/fine-tune

Использовать отдельное окружение WSL2/Linux с CUDA, Unsloth,
transformers v5, trl и datasets. Не устанавливать обучающие
библиотеки в рабочую .venv парсера. Обучение требует как минимум
100 train и 20 реальных validation-сообщений и не запускается
без явного параметра --run:

    python -m scripts.train_news_lora --model unsloth/Qwen3.5-2B --max-seq-length 1024 --data-dir training/news_sft
    python -m scripts.train_news_lora --model unsloth/Qwen3.5-2B --max-seq-length 1024 --data-dir training/news_sft --max-steps 250 --run

После обучения LoRA сохраняется локально. Её нужно отдельно
проверить на полностью новых реальных статьях, экспортировать
в GGUF/Ollama и убедиться в совпадении chat template. Пока
автоматическая публикация не подключается.

## Проверка Qwen3.5-4B на 25 статьях (08.11.2026)

Отчёт `llm_fresh25_v2.json`: 25 реальных записей, из них
9 получили сводку, 12 отклонены как непрофильные, 4 вызвали
отказ `LLM придумала или исказила цитату источника`.
Успешные сводки имеют длины 366, 383, 492, 314, 394, 321,
241, 262, 357 символов. Среднее **347,8**,
7/9 в диапазоне 250–400, 2/9 вне целевого, но в пределах
допустимого 550. Избыточная краткость перестала быть главной
проблемой.

**Сравнение с предыдущим read-only аудитом** на тех же 25 URL
при пороге 0.35 (эталонные метки все `draft`, не gold):

| Вариант | TP | FP | FN | micro-F1 | Exact |
|---|---:|---:|---:|---:|---:|
| SBERT legacy | 6 | 16 | 12 | 0.300 | 7/25 |
| SBERT hybrid | 6 | 15 | 12 | 0.308 | 9/25 |
| Qwen3.5-4B | 5 | 13 | 13 | 0.278 | 11/25 |

Для Qwen 4 ошибки цитирования считаются пропусками.
На 12 статьях с пустыми draft-эталонами Qwen ошибочно выдала
теги 1 раз против 4 у гибрида, но обнаружено два пропуска
положительных статей без ошибки генерации. Вывод о превосходстве
на реальных данных делать нельзя.

**Смысловые искажения при формально проверенных цитатах:**
- платино-палладиевые материалы: плотность палладия вдвое
  меньше, но нельзя утверждать, что ВЕС изделия точно
  уменьшается вдвое; мировые 700 тыс. унций и китайские
  3,5 млн унций в источнике относятся к контекстам, которые
  нельзя сводить в простое сравнение;
- скандий РУСАЛ: будущее поглощение CO2 подано как
  уже происходящее, атрибуция изготовителя оборудования
  сильнее, чем утверждение источника;
- Hyundai WIA: вложенные ранее 15,8 млрд рублей описаны
  так, будто относятся к планируемому возобновлению работы;
- ингибитор газогидратов: «почти не растёт» превращено
  в «падает».

**Важно:** наличие source quote и отсутствие новых чисел
НЕ доказывает сохранение смысла. До автоматической публикации
нужен независимый контроль утверждений, числовых связей,
исполнителей действий и статуса план/факт. Пока
`review_required=true` для всех профильных статей,
фактической публикации нет.

Добавлена **одна безопасная повторная попытка** при неточной
цитате: модель заново копирует дословные фрагменты из статьи;
если проверка снова не проходит, статья остаётся отложенной.
Это общее улучшение отказоустойчивости, не подгонка тегов
под 25 новостей. Повторные реальные вызовы после исправления
пока не проводились.

## Повторная проверка после добавления retry цитат (25 статей)

Файл `llm_fresh25_retry.json`, локальная модель `qwen3.5:4b`.
Сравнивался с `llm_fresh25_v2.json` по URL, без изменений
валидационной разметки. **Это не независимый новый тест**:
25 статей уже неоднократно использовались при разработке.

| Показатель | До retry | После retry |
|---|---:|---:|
| Всего статей | 25 | 25 |
| С непустым summary | 9 | 12 |
| Отклонены как нерелевантные | 12 | 11 |
| Ошибка цитирования (relevant=null) | 4 | 2 |
| TP / FP / FN по draft-меткам | 5 / 13 / 13 | 6 / 18 / 12 |
| Micro-F1 по draft-меткам | 0.2778 | 0.2857 |
| Exact match по draft-меткам | 11/25 | 10/25 |
| Ложно размеченных из 12 draft-непрофильных | 1 | 2 |

В новом прогоне стали успешно обрабатываться:
- датчик для метанольного реактора (раньше error, теперь
  «химическая промышленность» + «технологическое производство»,
  при draft-эталоне «электротехническое направление»);
- модернизация вагоноопрокидывателя «Остерры» (раньше error,
  теперь «машиностроение» + «технологическое производство»,
  при draft-эталоне «инжиниринг»).

Не обрабатываются после обновления:
- внешний управляющий на «Борхиммаше»;
- калориферные установки для рудников.

**Новая ложная позитивная статья:** выпуск мальков осетра
«Норникелем» теперь получает «технологии» + «инновации».
Другая ложная позитивная статья — юбилей Артёмовской ТЭЦ,
в обоих прогонах.

Только поле error не позволяет узнать, применялся ли retry
для отдельных успешных новостей: повторный запуск мог получить
другой ответ и с первого запроса, несмотря на temperature=0.
Нельзя приписать оба исправления исключительно механизму retry
без отдельной телеметрии числа попыток.

Новые summary: 12 непустых, средняя длина 344,8 символа;
8 из них в целевом диапазоне 250–400, две короче, две длиннее
(максимальная длина 507), все в пределах 550.
Смысловые искажения **не устранены**: плотность материала
путается с массой изделия, исторические затраты с будущими,
будущий эффект с текущим, а «почти не растёт» с «падает».
Не использовать warnings=[] как проверку фактической
правильности. До независимой проверки — **никакой автоматической
публикации LLM summary в MAX**.

Разметка `tagging_reference_fresh_25.json` остаётся `draft`,
включает спорные отраслевые метки и редакционные решения;
это ориентировочные, не итоговые метрики.

## Критерии готовности

- Тегирование: точность, полнота, F1 по темам, ложные теги у
  непрофильных новостей, правильность главного объекта события.
- Сводка: фактическая точность всех утверждений, чисел, дат,
  названий, отсутствующие в источнике детали, стиль русского языка.
- Автономность: локальная скорость, стабильный JSON, отказ от
  публикации при ошибках, повторная обработка, мониторинг качества.
- Объективная проверка: только независимые и проверенные РЕАЛЬНЫЕ
  новости — синтетические метрики не заменяют её.
