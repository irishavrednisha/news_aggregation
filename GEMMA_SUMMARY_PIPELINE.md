# Пайплайн сводок: TextRank → Gemma → редакторская проверка

Сбор, фильтрация и кластеризация не изменены. Основной пайплайн
из main.py вызывает summarize_new_clusters(). Теперь TextRank в
processing/summarizer.py сначала выбирает предложения из текста источника,
а processing/summary_pipeline.py направляет выбранный TextRank-текст
локальной Gemma для перефразирования. **По умолчанию Gemma видит всю
выбранную сводку как один блок и возвращает один связный абзац**. Она
не получает полную статью, не выбирает новые факты и не назначает теги.
Старый режим предложения-к-предложению остаётся доступным для сравнения.

## Запуск локально (Windows, PowerShell)

1. Установить Ollama и скачать модель: ollama pull gemma3:4b
2. Запустить Ollama; API должен отвечать на 127.0.0.1:11434.
3. По умолчанию работает NEWS_SUMMARY_BACKEND=gemma,
   NEWS_GEMMA_MODEL=gemma3:4b и NEWS_GEMMA_REWRITE_MODE=whole.
   Для старого режима можно установить:
   $env:NEWS_GEMMA_REWRITE_MODE = "aligned"
   Для исходного TextRank использовать:
   $env:NEWS_SUMMARY_BACKEND = "textrank"
4. Запустить основной пайплайн как раньше.

Модель вызывается только через локальный Ollama API. Cloud-модели
нельзя указывать. GitHub хранит код; он не выполняет сводки вместо
локального компьютера.

## Как работает защита от выдуманных фактов

В режиме whole Gemma возвращает JSON с одним полем summary — связный
текст вместо списка предложений. Она может объединять предложения, но
не должна изменять факты. В режиме aligned по-прежнему возвращается
JSON с тем же количеством предложений и в прежнем порядке.
Проверяется наличие чисел и их ближайших единиц измерения/объектов,
названия в кавычках, новые имена с прописной буквы, отрицания,
указания на планы и завершённые действия, длина и формат текста.

Если модель ошиблась, недоступна или не прошла эти проверки, исходный
TextRank остаётся в базе. Это буквальные предложения источника, а не
перефразированный текст.

**Любой вызов Gemma, включая отклонённое перефразирование и fallback,
переводит непустую сводку в статус `review_required`.** Тэггер
обрабатывает этот кластер, но сохраняет статус. Публикатор выбирает
только ready, поэтому без ручной сверки по первоисточнику НИ черновик,
НИ исходный TextRank после неудачного вызова Gemma не попадут в MAX.
Опубликованные кластеры не пересуммаризируются. Без тегов публикации нет.

По результатам gemma5.json (5 материалов, 1 формально принятый вариант)
обнаружена смысловая ошибка: «CO2 будет поглощаться» заменено на
«будет выбрасываться». Добавлена проверка противоположных направлений
технических действий (поглощение/выброс, рост/снижение,
одобрение/отклонение). Исправлена обработка сокращений «тыс.» и «кв.»
в разбиении предложений TextRank. Такие проверки предотвращают
некоторые, но не все смысловые ошибки.

Кроме модели, нужно проверять исходный текст: например, материал
о Норникеле и Красцветмете содержит странную ссылку на
пресс-службу ОДК-Кузнецов; дословное извлечение не исправляет
противоречия в самом источнике.

ВАЖНО: формальные проверки не гарантируют сохранение смысла. Модель
может изменить причинность, объект или условия, не меняя чисел.
Проверка человеком по первоисточникам обязательна.

Для ручной проверки и разрешения публикации кластера 123 выполнить:

    .\.venv\Scripts\python.exe scripts\review_gemma_summary.py --cluster-id 123

Скрипт покажет переписанную сводку, оригинальные тексты, заголовки,
ссылки и теги. Разрешение публикации требует ручного ввода
ПОДТВЕРЖДАЮ. Не подтверждать сводку до проверки каждого утверждения.

## Аудит второго прогона: gemma10_v2.json

На 10 новостях модель смогла перефразировать 4, вернула TextRank для 6.
**Доля принятия 40% не означает фактическую точность 40%.**

- РУСАЛ: модель переписала будущее «инвестиции составит» как
  прошедшее «составил»; старый валидатор принял результат без предупреждений.
  Добавлен контроль перехода будущего в прошедшее и обратно для
  типичных глаголов промышленной хроники.
- «Норникель»/Красцветмет: модель приняла неоднозначное указание
  на «ОДК-Кузнецов» из исходного текста. Нужна проверка
  согласованности заголовка с оригинальной статьёй.
- Госдума, аттракционы: формально принятый пересказ не обязательно
  относится к промышленному производству; это задача фильтра/тэггера.
- Программа «Стимул»: TextRank выбрал контекстно неполные фразы
  («Мы буквально вчера», «по ней», «а мы тут»). Сводка не готова.
- Автокомпоненты и VOTOUR: модель меняет «2 млн.» на «2 миллиона»,
  «200 тыс.» на «200 тысяч»; строгий валидатор возвращает TextRank.
  Это может быть лингвистически эквивалентно, но несовместимо с
  заданным правилом дословного сохранения чисел и единиц измерения.
- Ростех, датчик: Gemma добавила «чем у зарубежных аналогов», которого
  нет в выбранном предложении. Добавлен запрет нового объекта
  явного сравнения.
- ЗИС: перефразирование прошло, но унаследовало грамматическую
  ошибку из исходного предложения («Предприятие выпустил»).
- Mazda/Владивосток: исходные «телевизоров» превращались в
  «евизоров». Причина в `utils/text_utils.py`: удаление префикса
  `тел` без границы слова. Исправлено. **Старые JSON и записи базы
  не исправляются автоматически**; для проверки надо собрать
  исходные статьи заново после обновления кода.
- Калининград, торги рыбозавода: модель не перефразировала текст;
  сам сюжет — продажа имущества, а не производственное событие.

Ни один из этих результатов не является подтверждением
фактической эквивалентности; автопубликация остаётся закрытой.
Все изменения в обработке текста и валидаторе должны пройти
регрессионные тесты и повторный локальный тест модели.

## Режим редактора с минимальными правками

Оба промпта теперь требуют **не переписывать хорошие предложения ради
синонимов**: исправлять только явные ошибки, избыточные повторы
или неудобные переходы, не дополняя факты. Если исходная TextRank-сводка
уже ясная, Gemma вправе вернуть её дословно — это корректный исход,
а не ошибка. Режим `whole` позволяет редактировать связность, а
`aligned` сохраняет предложение-к-предложению.

Новый отчёт тестового скрипта отдельно показывает:
`rewritten_count` (редактура выполнена), `unchanged_count` (правки
не нужны), `rejected_count` (модель выдала недопустимое изменение).
Старое `fallback_count` сохранено для совместимости и включает
все результаты без редакторских изменений. **Все три исхода остаются
черновиками с обязательной ручной проверкой.**

## Эксперимент: связный абзац против предложения-к-предложению

Режим whole не гарантирует меньшего числа галлюцинаций: объединение
предложений может перепутать субъекты, сроки и числовые показатели.
Поэтому оба режима сравниваются на **одинаковых** TextRank-источниках,
с ручной проверкой по первоисточникам. Оба отчёта read-only,
ничего не публикуют. Процент переписанных текстов не является
оценкой достоверности.

## Следующий этап: тэггирование

Режимы legacy, hybrid и nli оставлены совместимыми. Новая сводка
не делает тэггирование более достоверным автоматически. Для оценки
нужна независимая разметка реальных новостей: precision, recall и F1
по каждой из 18 тематик, а также отдельная проверка смешанных
производственных событий, беспилотников и судостроения. Следующий
эксперимент — сравнить legacy и hybrid на идентичном наборе новостей,
не используя результаты Gemma в качестве эталонных меток.
