# Пайплайн сводок: TextRank → Gemma → редакторская проверка

Сбор, фильтрация и кластеризация не изменены. Основной пайплайн
из main.py вызывает summarize_new_clusters(). Теперь TextRank в
processing/summarizer.py сначала выбирает предложения из текста источника,
а processing/summary_pipeline.py направляет только выбранные предложения
локальной Gemma для перефразирования. Gemma не выбирает новые факты и
не назначает тематические теги.

## Запуск локально (Windows, PowerShell)

1. Установить Ollama и скачать модель: ollama pull gemma3:4b
2. Запустить Ollama; API должен отвечать на 127.0.0.1:11434.
3. По умолчанию работает NEWS_SUMMARY_BACKEND=gemma и
   NEWS_GEMMA_MODEL=gemma3:4b. Для исходного TextRank использовать:
   $env:NEWS_SUMMARY_BACKEND = "textrank"
4. Запустить основной пайплайн как раньше.

Модель вызывается только через локальный Ollama API. Cloud-модели
нельзя указывать. GitHub хранит код; он не выполняет сводки вместо
локального компьютера.

## Как работает защита от выдуманных фактов

Gemma возвращает JSON с тем же количеством предложений и в том же порядке.
Проверяется наличие чисел и их ближайших единиц измерения/объектов,
названия в кавычках, новые имена с прописной буквы, отрицания,
указания на планы и завершённые действия, длина и формат текста.

Если модель ошиблась, недоступна или не прошла эти проверки, исходный
TextRank остаётся в базе. Это буквальные предложения источника, а не
перефразированный текст.

Если модель успешно переписала предложения, кластер получает статус
review_required. Тэггер обрабатывает этот кластер, но сохраняет статус.
Публикатор выбирает только ready, поэтому без редакторской проверки
перефразированная сводка НЕ попадает в MAX. Опубликованные кластеры
не пересуммаризируются. Без тегов публикации нет.

ВАЖНО: формальные проверки не гарантируют сохранение смысла. Модель
может изменить причинность, объект или условия, не меняя чисел.
Проверка человеком по первоисточникам обязательна.

Для ручной проверки и разрешения публикации кластера 123 выполнить:

    .\.venv\Scripts\python.exe scripts\review_gemma_summary.py --cluster-id 123

Скрипт покажет переписанную сводку, оригинальные тексты, заголовки,
ссылки и теги. Разрешение публикации требует ручного ввода
ПОДТВЕРЖДАЮ. Не подтверждать сводку до проверки каждого утверждения.

## Проверки без публикации

Пробный отчёт на реальных новостях без БД и без MAX:

    .\.venv\Scripts\python.exe check_extractive_rewrite.py tagging_fresh_25.json --limit 5 --model gemma3:4b --output collector_test_results/gemma5.json

Юнит-тесты без Ollama и загрузки весов:

    .\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_summary_pipeline.py" -v
    .\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_extractive_rewriter.py" -v

## Следующий этап: тэггирование

Режимы legacy, hybrid и nli оставлены совместимыми. Новая сводка
не делает тэггирование более достоверным автоматически. Для оценки
нужна независимая разметка реальных новостей: precision, recall и F1
по каждой из 18 тематик, а также отдельная проверка смешанных
производственных событий, беспилотников и судостроения. Следующий
эксперимент — сравнить legacy и hybrid на идентичном наборе новостей,
не используя результаты Gemma в качестве эталонных меток.
